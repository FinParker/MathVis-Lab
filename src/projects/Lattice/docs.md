# 格 (Lattice) 与类型系统

在计算机科学和数学中，**格（Lattice）**和**布尔格（Boolean Lattice）**是代数结构，它们为理解类型系统、权限管理以及你提到的“继承关系”提供了坚实的数学基础。

## 1. 什么是格 (Lattice)？

从直观上讲，**格**是一种特殊的“偏序集”。在这一组元素中，任意两个元素 $a$ 和 $b$ 都存在两个确定的值：

1. **最小上界（Join / 上确界）：** 记作 $a \vee b$，通俗理解就是两者的“最小共同上级”。
2. **最大下界（Meet / 下确界）：** 记作 $a \wedge b$，通俗理解就是两者的“最大共同下级”。

### 2. 什么是布尔格 (Boolean Lattice)？

布尔格是格的一种特殊形式（它必须是有界、分配且有补的）。最经典的例子就是**集合的幂集**。

* **并集 ($\cup$)** 是最小上界。
* **交集 ($\cap$)** 是最大下界。
* 每个元素都有一个完全相反的**补集**。

## 3. 格与 OOP 继承的关系

在面向对象编程（OOP）中，**类型系统其实就是一个格**。

* **继承关系 = 偏序关系：** 如果 `Class B` 继承自 `Class A`，我们可以说 $B \le A$（B 是 A 的子类型）。
* **顶（Top, $\top$）：** 格的最顶端。在 Java 中是 `Object`，在 Scala 中是 `Any`。所有类型的最小上界最终都会汇聚于此。
* **底（Bottom, $\perp$）：** 格的最底端。代表“没有任何值”的类型。在 Scala 中是 `Nothing`，在 Rust 中是 `!` (Never type)。

### 为什么理解这个很重要？

当你写出 `var x = if (condition) new Dog() else new Cat()` 时，编译器必须找到 `Dog` 和 `Cat` 的**最小上界（LUB）**。这个过程就是在格结构中向上回溯，寻找它们共同的父类。

## 4. 类型系统中的格

### TypeScript: 完美的格实现

在主流语言中，TypeScript 的类型系统是对“格（Lattice）”理论实现得最直观、最彻底的。

#### **Top & Bottom**
* **`unknown` (Top Type $\top$):** 它是格的最顶端。
* **`never` (Bottom Type $\perp$):** 它是格的最底端。

#### **Union & Intersection**
* **联合类型 `|` (Join / $\vee$):** 寻找最小上界。
* **交叉类型 `&` (Meet / $\wedge$):** 寻找最大下界。

### Rust: Trait 构成的格
Rust 没有传统的类继承，但其 **Trait（特征）** 系统构成的类型关系非常符合格的定义。`!` 类型作为 Bottom 类型。

### Java: 不完美的格
Java 的类继承是单继承树。但在引入接口（Interface）后，它变得更像一个格。
